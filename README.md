# 公共財ゲーム（ホスト用）

授業で「公共財ゲーム（Public Goods Game）」を行うための、教員（ホスト）用の画面です。
参加者（生徒）用の画面は [public-goods-game](https://github.com/xin1zu2zhai1/public-goods-game) リポジトリにあります。

- ホスト画面：https://xin1zu2zhai1.github.io/public-goods-host/
- 参加者画面：https://xin1zu2zhai1.github.io/public-goods-game/

サーバーやデータベースは用意する必要がありません。教員のブラウザが「親機」になり、生徒のスマホと次の3つの経路でつながります。
まず直接つなぎに行き、2.5秒たってもつながらなければ中継も同時に試して、最初につながった経路を使います。

- **直接**：ブラウザ同士で直接通信（WebRTC / PeerJS）。同じWi-Fiの教室などではこれでつながります。
- **PeerJS 中継**：直接通信の仲介に使う PeerJS のサーバー（`0.peerjs.com`、443番）に、メッセージを転送してもらいます。
  スマホのモバイル回線など、直接つながらない環境向けです。
- **MQTT 中継**：公開の MQTT ブローカー経由。PeerJS のサーバーが使えないときの予備です。

中継される内容は、ホストと参加者の端末ごとの鍵で暗号化される（ECDH + AES-GCM）ので、中継サーバーからは読めません。

## 公開の準備（最初に1回だけ）

2つのリポジトリそれぞれで GitHub Pages を有効にします。

1. リポジトリの **Settings → Pages** を開く
2. **Build and deployment** の Source で **Deploy from a branch** を選ぶ
3. Branch を **main**、フォルダを **/ (root)** にして **Save**
4. 数分後に上記の URL で開けるようになります

## 授業での使い方

1. 教員のPCでホスト画面を開き、プロジェクターに映します。ルームコード（6けた）とQRコードが表示されます。
2. 生徒はスマホのカメラでQRコードを読み取り、ニックネームを入れて「参加する」を押します。
   QRが使えない場合は、参加者画面を開いてルームコードを入力します。**人数の上限はありません。**
3. 「ラウンド1を開始」を押すと、参加者が自動で4人ずつのグループに分かれ、生徒の画面に入力画面が出ます。
4. 生徒は持ち金 1,000円 のうち、共有財産に出す金額を決めて送信します。
   全員がそろうと自動で締め切られます（「締め切る」ボタンで手動でも締め切れます。未入力の人は 0円 として計算します）。
5. 生徒の画面に結果が表示されます：自分の利得の計算過程、グループのメンバーが出した額（A・B・C… の匿名表示）、
   これまでの推移のグラフ。ホスト画面には、クラス全体の平均拠出額の推移・幸福度・分布が表示されます。
6. 「ラウンド2を開始」…と繰り返します（ステージ1は5回程度が目安）。
7. **罰則ルール**のスイッチをオンにすると、次のラウンドから「罰則フェーズ」が加わります（ステージ2）。
   生徒は結果を見て、ほかのメンバーに罰を与えるかを決めます（初期設定：100円払うと相手が300円減る）。
   スイッチはいつでもオン・オフできます。切り替えるたびにステージ番号が変わり、グラフに色が付きます。
8. 「ゲームを終了」を押すと、生徒の画面に最終結果と振り返りの問いが表示されます。
   振り返り欄の「匿名コメントを受け付ける」をオンにすると、生徒が名前なしでコメントを送れます（ホスト画面で「隠す」こともできます）。
9. 「結果をCSVで保存」で、全員・全ラウンドの記録を Excel などで開ける形で保存できます。生徒も自分の記録を保存できます。

### 画面のボタン・設定

| 項目 | 内容 |
| --- | --- |
| 罰則ルール | オン／オフの切り替え。入力中のラウンドなら、そのラウンドから反映されます |
| 投影モード | ニックネームや設定など、教員だけが見るべき部分を隠します |
| 名前を表示 | グループ一覧に生徒のニックネームを表示します（初期はオフ） |
| グループを組み直す | 全員をシャッフルして新しいグループを作ります（ラウンドとラウンドの間で使えます） |
| ×（グループ一覧） | 参加者を外します（二重参加や欠席者の整理に） |
| ラウンドを取り消す | 操作ミスのとき、入力中のラウンドをなかったことにします |
| ゲームの設定 | 初期保有額・増殖係数・グループの人数・罰則の金額と回数・匿名表示・自動締め切り・参加受付 |

### 授業設計との対応

| 設計 | この画面での設定 |
| --- | --- |
| 4人1組 | 「1グループの人数」= 4人（端数が出たら3〜5人に調整） |
| 初期保有額 1,000円 | 「初期保有額」= 1,000 |
| 増殖係数 2倍 | 「増殖係数」= 2（「1.1倍だったら？」の問いを試すときは変更） |
| 利得 = (1,000 − 拠出額) + 2 × 合計 ÷ 4 | 生徒の結果画面に計算過程を表示 |
| ステージ1：標準ルールを5回程度 | 罰則オフで5ラウンド |
| ステージ2：処罰ルール（100円で相手を300円減らす） | 罰則オンにして続行 |
| 拠出額の推移をリアルタイムで提示 | ホスト画面のグラフ（罰則ありの期間は色付き） |
| グループ全体の幸福度（％） | 全員が全額出した場合を100%として表示 |
| 匿名での意見投稿 | 振り返りの匿名コメント |
| データを持ち帰ってレポート | ホスト・生徒ともにCSV保存 |

## 気をつけること

- **ホスト画面のタブは閉じないでください。** 教員のブラウザが親機なので、閉じると生徒とつながらなくなります。
  うっかり閉じたり再読み込みしても、同じPC・同じブラウザで開き直せば「続きから再開」できます（結果はブラウザに自動保存）。
- 生徒の通信が切れても自動で再接続します。生徒がページを閉じても、同じ端末で同じQRコードから開けば続きから参加できます。
- PCのスリープで通信が切れるので、授業中はスリープしない設定にしてください（対応ブラウザでは画面の消灯防止を自動で要求します）。
- ホスト画面右上の表示で通信の状態がわかります。例：「接続OK（PeerJS○・MQTT 0/4）」。PeerJS か MQTT のどちらかがつながっていれば参加できます。
  参加人数の下には「接続中 30人（うち中継 12人）」のように、中継でつながっている人数が出ます。生徒の画面右上にも「接続OK（直接）」「接続OK（中継）」と出ます。
- 使う外部サービス
  - 直接：接続の仲介に PeerJS の公開サーバー（`0.peerjs.com`）
  - PeerJS 中継：上と同じ `0.peerjs.com`
  - MQTT 中継：公開 MQTT ブローカー（`broker.emqx.io:8084`、`broker.hivemq.com:8884`、`mqtt.eclipseprojects.io:443`、`test.mosquitto.org:8081`）。
    ホストはすべてに、参加者はつながるものにつなぎ、両方がつながっているブローカーで通信します。学校などのネットワークでは使えないことがあります。中継されるのは暗号化されたデータだけで、ブローカーからはルームの中身（ニックネームや金額）は読めません。
- 学校のネットワークでは、WebRTC や一部のポートが制限されていることがあります。**授業の前に、教室のWi-Fiとモバイル回線の両方で、教員PCとスマホ2台程度で試してください。**
- 画面のいちばん下に版数（例：「版 1.2.0」）が出ます。新しい版を公開すると、ページを開いたときに自動で読み込み直します。
- ホスト画面の参加人数の下に「通信の状態：PeerJS（直接・中継）○ ・ MQTT中継 emqx○ hivemq× …」のように、経路ごとの接続状態が出ます。
- 参加者がつながらなかったときは、エラーの下に「詳細：PeerJSサーバー＝…／直接＝…／PeerJS中継＝…／MQTT中継＝emqx ○ホストなし、hivemq ×接続できない…」のように、経路ごとの状況が出ます。
  「PeerJSサーバー＝接続できない」なら、その回線から `0.peerjs.com` に届いていません（直接・PeerJS中継とも使えません）。
  「×接続できない」はその回線からそのサーバーに届いていない、「○ホストなし」はサーバーには届いたがホストの応答がない（ホスト画面が開いていない・コード違い・ホスト側がそのサーバーにつながっていない）ことを表します。
- うまくつながらないときの調べ方：参加者画面の URL の最後に `&transport=p2p`（直接だけ）、`&transport=sig`（PeerJS中継だけ）、`&transport=mqtt`（MQTT中継だけ）を付けて開くと、どの経路でつながるかを確かめられます。
- ニックネームはホストのブラウザにだけ保存されます。ほかの生徒には（「ニックネームを見せる」をオンにしない限り）A・B・C… の記号で表示されます。
- 動作確認は参加者20人（4人×5グループ。直接・中継それぞれ）で行っています。1クラス40人程度を想定しています。

## 開発者向け

```
index.html        ホスト画面
css/host.css
js/game.js        ゲームのルール・利得計算・グループ分け（DOMに依存しない）
js/app.js         画面と進行
js/net-host.js    直接通信（PeerJS / WebRTC）
js/relay.js       中継通信（PeerJS 中継・MQTT 中継、暗号化）。参加者側と同じファイル
js/config.js      参加者ページのURL・PeerID の接頭辞・中継ブローカーの一覧
js/chart.js       グラフ（SVG）
vendor/           PeerJS 1.5.5、MQTT.js 5.10.4、qrcode-generator 1.4.4（いずれも MIT ライセンス）
tests/            テスト
```

- `js/config.js` の `PEER_ID_PREFIX` は、参加者側リポジトリの `js/config.js` と同じ値にしてください。
- ホストと参加者の通信形式を変えたときは、`js/game.js` の `PROTOCOL_VERSION` と参加者側の `PROTOCOL_VERSION` を一緒に上げてください。
- 参加者ページの URL を変えたいときは、`js/config.js` の `DEFAULT_PLAYER_URL` を書き換えるか、ホスト画面の「ゲームの設定 → 詳細」で変更できます。
- 自前の PeerJS サーバーを使うときは、ホスト画面の URL に `?peer=ホスト名:ポート/パス` を付けます（QRコードにも引き継がれます）。
- 中継ブローカーを差し替えるときは、ホスト画面の URL に `?relay=wss://…/mqtt,wss://…/mqtt` を付けます（`?relay=off` で中継なし）。
  既定の一覧を変えるときは、両方のリポジトリの `js/config.js` の `RELAY_BROKERS` を同じ内容にしてください。
- `js/relay.js` はホスト側と参加者側で同じファイルです。変更したら両方にコピーしてください。
- ファイルを変更して公開するときは、`node scripts/set-version.mjs 1.2.1` のように版数を上げてください（両方のリポジトリで）。
  読み込むファイルの URL に版数が付くので、スマホなどに古いファイルが残っていても新しい版が使われます。

### テスト

```bash
npm test
```

ブラウザでの通しテスト（Playwright と PeerJS サーバー、WebSocket 対応の MQTT ブローカーが必要）：

```bash
npx peerjs --port 9000 --host 127.0.0.1
```

MQTT ブローカーを `ws://127.0.0.1:8883` で起動しておき（例：aedes + ws、mosquitto など）、

```bash
python3 -m http.server 8001
```

```bash
cd ../public-goods-game && python3 -m http.server 8002
```

```bash
N=6 RELAY=ws://127.0.0.1:8883 node tests/e2e.cjs
```

参加者の直接通信を止めて、中継だけで最後まで遊べるかを確かめる：

```bash
N=6 RELAY=ws://127.0.0.1:8883 BLOCK_P2P=1 node tests/e2e.cjs
```
